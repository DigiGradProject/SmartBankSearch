# شرح ملفات تقييم البحث

هذا المستند يشرح وظيفة مجموعات أسئلة التقييم الموجودة في:

- `tests/retrieval/golden_set.jsonl`
- `tests/retrieval/validation_set.jsonl`

هذه الملفات مخصصة لاختبار جودة نظام البحث، وليست جزءًا من المحتوى الذي يستخدمه النظام للإجابة عن أسئلة العملاء.

## الفكرة الأساسية

يمكن اعتبار كل سطر في هذه الملفات حالة اختبار مستقلة. يحتوي السطر على سؤال، والتصنيف المتوقع له، ومعلومة تساعد الاختبار على التأكد من أن النظام استرجع الصفحة الصحيحة.

مثال:

```json
{
  "query": "open bank account NBE",
  "language": "en",
  "intent": "account_open",
  "expected_url_contains": "Accounts",
  "forbidden_url_contains": "OpenYourBankAccountInEgypt"
}
```

معاني الحقول:

- `query`: السؤال الذي سيتم إرساله إلى نظام البحث أثناء الاختبار.
- `language`: لغة السؤال، مثل `ar` أو `en`.
- `intent`: نوع السؤال المتوقع، مثل `account_open` أو `certificate_buy`.
- `expected_url_contains`: نص يجب أن يكون موجودًا في رابط إحدى النتائج الصحيحة.
- `forbidden_url_contains`: نص لا يجب أن يظهر في روابط النتائج الأولى لأنه يشير إلى صفحة غير مناسبة للسؤال.

## Golden Set: عددها 22 سؤالًا

الملف `golden_set.jsonl` يحتوي على 22 سؤالًا مرجعيًا تغطي الوظائف الأساسية، مثل:

- أسعار العملات وتحويل العملات.
- فتح الحسابات والمستندات المطلوبة.
- القروض الشخصية.
- بطاقات الائتمان وأنواع البطاقات.
- شراء الشهادات وأسعار العائد.
- الفروع وماكينات الصراف الآلي.
- العروض وخدمات الشركات والمشروعات الصغيرة.

هذه المجموعة تستخدم كمرجع أساسي أثناء تطوير وضبط الاسترجاع وتصنيف النوايا. لا يكفي الاعتماد عليها وحدها، لأن النظام قد يصبح مضبوطًا على صياغاتها المحددة بدلًا من فهم صياغات جديدة.

## Validation Set: عددها 220 سؤالًا

الملف `validation_set.jsonl` يحتوي على 220 صياغة مختلفة لاختبار قدرة النظام على التعميم. قد تعبّر عدة أسئلة عن المعنى نفسه بطرق مختلفة، مثل:

```text
فتح حساب بنكي
إيه الأوراق المطلوبة لفتح حساب؟
عايز أفتح حساب في البنك الأهلي
How can I create an NBE account?
```

الهدف هو التأكد من أن النظام يفهم المعنى، وليس أنه حفظ نصوص أسئلة الـ Golden Set.

تم إنشاء جزء كبير من مجموعة الـ Validation كإعادة صياغة منظمة للأسئلة المرجعية. لذلك هي مفيدة لاختبار تنوع الصياغة، لكنها لا تُغني عن إضافة أسئلة حقيقية مجهولة المصدر من المستخدمين بعد تنقيح أي بيانات حساسة منها.

## كيف يتم تنفيذ التقييم؟

عند تشغيل سكربت التقييم، يمر كل سؤال بالمراحل التالية:

```text
سؤال الاختبار
    ↓
اكتشاف اللغة وتصنيف Intent
    ↓
البحث الدلالي وBM25
    ↓
إعادة ترتيب النتائج
    ↓
مقارنة النتائج بالـ expected والـ forbidden
    ↓
حساب مؤشرات الجودة والسرعة
```

السكربتات الأساسية:

- `scripts/eval_retrieval.py`: تقييم أساسي متوافق مع الـ Golden Set.
- `scripts/eval_retrieval_modes.py`: مقارنة بين وضعي `PURE_SEMANTIC` و`ENTERPRISE`.
- `scripts/eval_metrics.py`: تنفيذ معادلات مؤشرات التقييم.
- `scripts/generate_validation_set.py`: توليد صياغات الـ Validation بطريقة منظمة.

## معنى الـ Matrix والـ Metrics

الـ Matrix المقصودة هي جدول نتائج التقييم، وليست بيانات يتم إرسالها إلى الـ LLM. مثال مبسط:

| Query | Intent صحيح | Top 1 صحيح | موجود في Top 3 | Confidence صحيح |
|---|---:|---:|---:|---:|
| open bank account | نعم | نعم | نعم | نعم |
| buy certificate | نعم | لا | نعم | نعم |
| exchange rates | نعم | نعم | نعم | نعم |

المؤشرات المحسوبة تشمل:

- `Intent Accuracy`: نسبة الأسئلة التي تم تصنيف نوعها بصورة صحيحة.
- `Top1`: نسبة الحالات التي ظهرت فيها الصفحة الصحيحة كأول نتيجة.
- `Top3`: نسبة الحالات التي ظهرت فيها الصفحة الصحيحة ضمن أول ثلاث نتائج.
- `Recall@5`: هل ظهرت نتيجة صحيحة واحدة على الأقل ضمن أول خمس نتائج.
- `MRR`: يقيس ترتيب أول نتيجة صحيحة؛ كلما ظهرت أبكر كانت القيمة أعلى.
- `nDCG@5`: يقيس جودة ترتيب النتائج الصحيحة داخل أول خمس نتائج.
- `Confidence Accuracy`: هل قرر النظام الإجابة أو الامتناع بصورة مناسبة.
- `Latency`: زمن تنفيذ البحث، ويشمل المتوسط و`p95`.

## الفرق بين PURE_SEMANTIC وENTERPRISE

- `PURE_SEMANTIC`: يقيس أداء البحث الدلالي والـ reranker بدون قواعد الأعمال المساعدة.
- `ENTERPRISE`: يشغّل المسار الكامل، بما في ذلك فلاتر metadata وقواعد الأعمال والصفحات canonical عند الحاجة.

المقارنة بين الوضعين توضح مقدار التحسن الناتج عن منطق النظام الإضافي، وتكشف أيضًا إذا كانت القواعد اليدوية ترفع الدقة على حساب التعميم أو السرعة.

## هل تؤثر هذه الملفات على إجابات المستخدمين؟

لا. مسار التشغيل الفعلي هو:

```text
سؤال العميل
    ↓
تحديد Intent
    ↓
البحث في الـ chunks المفهرسة
    ↓
إعادة الترتيب وبناء السياق
    ↓
إنشاء الإجابة والمصادر
```

ملفات `golden_set.jsonl` و`validation_set.jsonl` لا تدخل في هذا المسار. لا تتم إضافتها إلى الـ prompt ولا إلى قاعدة المتجهات، ولا يستخدمها الـ LLM لصياغة الإجابة. تتم قراءتها فقط عند تشغيل سكربتات التقييم.

## أوامر التشغيل

من داخل مجلد `nbe-ai-search-mvp`:

```bash
set PYTHONPATH=.
python scripts/eval_retrieval.py --report --gate
```

على Linux أو macOS:

```bash
PYTHONPATH=. python scripts/eval_retrieval.py --report --gate
```

لتقييم مجموعة الـ Validation ومقارنة الوضعين:

```bash
PYTHONPATH=. python scripts/eval_retrieval_modes.py --mode both --report
```

لتقييم الـ Golden Set باستخدام المقارنة الجديدة:

```bash
PYTHONPATH=. python scripts/eval_retrieval_modes.py --golden --mode both --report
```

ويمكن حفظ النتيجة في JSON:

```bash
PYTHONPATH=. python scripts/eval_retrieval_modes.py --mode both --out reports/retrieval-comparison.json
```

## متى نضيف سؤالًا جديدًا؟

أضف حالة جديدة عندما:

- يظهر سؤال حقيقي يتم تصنيفه إلى Intent خاطئ.
- تكون الإجابة صحيحة لكن المصدر أو الرابط غير صحيح.
- تظهر صفحة غير مناسبة ضمن النتائج الأولى.
- يجيب النظام رغم عدم وجود دليل كافٍ.
- يمتنع النظام عن الإجابة رغم وجود صفحة واضحة في الفهرس.

أمثلة مناسبة للإضافة بعد المشكلات التي تم اكتشافها:

```json
{"query":"open bank account NBE","language":"en","intent":"account_open","expected_url_contains":"SavingLocalCurrency"}
{"query":"al ahly points","language":"en","intent":"general_faq","expected_url_contains":"ahlypoints","forbidden_url_contains":"ExchangeRates"}
```

## هل نحذف هذه الملفات؟

لا يُنصح بحذفها. وجود مجموعة مرجعية صغيرة ومجموعة Validation أكبر يساعد على:

- اكتشاف الـ regressions بعد تعديل الكود.
- منع إصلاح سؤال واحد على حساب أسئلة أخرى.
- مقارنة إصدارات البحث بصورة رقمية.
- قياس الفرق بين البحث الدلالي الخام والمسار الكامل.

الأفضل مستقبلًا هو الاحتفاظ بالمجموعتين، وإضافة مجموعة ثالثة من أسئلة مستخدمين حقيقية بعد إزالة أي بيانات حساسة، وعدم استخدامها أثناء ضبط القواعد أو الـ prompts حتى تظل اختبارًا مستقلًا فعليًا.
